A meta description does not help you rank. It decides whether the ranking is worth anything. On a page sitting at position six with a good impression count and few clicks, the description is often the entire problem, and it is one of the cheapest things on a site to fix.

## Write for the query the page actually ranks for

The most common failure is writing the description for the keyword you targeted, when the page has drifted and now earns its impressions from a different query. Pull the top query per URL out of Search Console first. That is what searchers are actually typing when they see this page, and it is frequently not what the brief said.

This is also the single biggest lever on whether Google keeps your description. Google rewrites a description when it thinks page text answers the query better. Writing to the live query removes most of that motivation.

## Front-load everything

Truncation happens from the end. Whatever sits in the last third of the description may simply never appear, and it varies by device. The working rule is that the first 120 characters must carry the whole message on their own. Treat anything after that as a bonus that some readers will see.

This is why the character-count debate is mostly a distraction. Google truncates on pixel width, so two descriptions of identical length can truncate differently depending on the characters used. Front-loading makes the question moot.

## Five patterns that work

| Pattern | Shape | Best for |
| --- | --- | --- |
| Direct answer | State the answer, then say what else the page covers | Informational queries |
| Outcome | Name what the reader will be able to do afterwards | How-to and guides |
| Specific scope | State exactly what is and is not included | Comparison and listicles |
| Objection | Name the doubt the searcher already has and address it | Commercial pages |
| Method | Say what the recommendation is based on | Anything where trust is the barrier |

The objection pattern is underused. Somebody searching a commercial query usually arrives with a specific hesitation, and a description that names it out loud tends to outperform one that lists features.

## Add information, do not restate the title

If the title is "SERP Analysis: How to Read a Search Result Page", the description should not be "Learn how to read a search result page." That is the same sentence twice, and it wastes the only extra line you get. Say what the reader gets: the checks, the template, the decision it produces.
